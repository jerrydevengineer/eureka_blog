# 데이터 관리, 조회와 정렬

## 데이터 관리

DBMS에서 데이터 관리란 데이터 삽입, 수정, 삭제가 있습니다. 각각의 sql문은 insert, update, delete이며 각각의 예시는 아래와 같습니다.

```sql
INSERT INTO table (c1, c2, c3) values (v1, v2, v3); -- insert

UPDATE table SET status = 's', quantity = '1' where id = '1'; -- update

DELETE FROM table where id = '1'; -- delete
```

이렇게 data를 관리할 때는 `commit`, `rollback`을 사용해 데이터 원자성을 지켜줘야 합니다(특히 여러 개의 데이터 관리 작업이 하나의 논리적 이벤트에서 여러 번 일어날 때 혹은 여러 데이터에 반복적으로 데이터 관리가 일어날 때).

## 데이터 조회

데이터 조회는 select문을 사용하여 원하는 조건의 데이터를 검색 및 원하는 컬럼만 추출해서 데이터를 가져오는 기능입니다.

```sql
SELECT c1, c4, c5 from table where id = '1'; -- select
```

원하는 조건을 where 절에 작성하고 select 뒤에 원하는 컬럼을 작성할 수 있습니다. 이 때 where 절에 많이 사용되는 컬럼이 있다면 index를 지정해 줄 수 있고, pair로 index를 설정할 수도 있습니다(where 절 내 작성 순서도 중요). 하지만 index 관리 또한 메모리 공간을 차지하고 삽입, 삭제 시에 추가 작업이 들어가므로 trade-off를 고려하여 생성하는 것이 중요합니다.

## 데이터 정렬

데이터 정렬은 select로 추출한 데이터들을 원하는 기준으로 정렬하는 방법이며, order by를 사용하여 실행할 수 있습니다.

```sql
SELECT * from table order by created_date desc; -- order by
```

기본적으로 order by 컬럼을 사용해서 오름차순으로 정렬할 수 있고, desc를 추가해서 내림차순으로 할 수도 있습니다. 또한 여러 컬럼을 사용해서 정렬할 수 있으며, 이 때 먼저 작성된 컬럼이 더 높은 우선순위를 가집니다. 이렇게 정렬을 할 때도 정렬 기준 컬럼에 index가 지정되어 있지 않다면 테이블을 full scan한 뒤에 정렬이 일어나게 되므로 검색하는 데이터의 행 수가 많다면 정렬 기준 컬럼에 인덱스를 지정하는 것도 고려해 볼 수 있습니다.

# 데이터 가공, 집계와 그룹핑

## 데이터 가공

RDBMS에서는 데이터를 추출한 뒤에 가공한 뒤로 데이터를 어플리케이션 측으로 보내줌으로써 네트워크 대역폭 및 어플리케이션 서버 메모리 부하를 줄여줄 수 있습니다. 데이터의 문자열 변환, 날짜 컬럼에서 필요한 데이터만 추출, case 문을 이용한 라벨링 등이 있습니다.

```sql
SELECT CONCAT(name, ' ', last_name) AS full_name from customers; -- string concat
SELECT order_id, DATE(created_at) AS order_date from orders; -- date
SELECT CASE WHEN status = 'delivered' then 'D'
			WHEN status = 'pending' then 'P'
			ELSE 'X'
		END AS status_c FROM orders; -- case
```

## 데이터 집계

RDBMS에서는 추출된 데이터로 수를 세거나 컬럼의 데이터로 계산을 하는 것이 가능합니다.

```sql
SELECT COUNT(1) as total_customers FROM customers; -- count
SELECT SUM(quantity * price) as total_price FROM orders; -- sum
SELECT AVG(quantity * price) as avg_price FROM orders; -- avg
SELECT MAX(quantity * price) as max_price FROM orders; -- max
SELECT MIN(quantity * price) as min_price FROM orders; -- min
```

이렇게 원하는 컬럼의 데이터를 어플리케이션에서 계산하지 않고 필요한 값을 미리 계산한 뒤로 가져와서 리소스를 줄일 수 있습니다.

## 데이터 그룹핑

RDBMS에서는 기준 컬럼으로 그룹을 만들어주고 해당 기준에 대한 계산을 해주는 group by도 사용할 수 있습니다.

```sql
SELECT customer_id, COUNT(order_id) AS total_orders 
FROM orders 
GROUP BY customer_id;

SELECT customer_id, COUNT(order_id) AS total_orders 
FROM orders 
GROUP BY customer_id 
HAVING COUNT(order_id) > 10;
```

또한 `having` 절을 사용해 그루핑된 컬럼의 집계에 대해 조건을 줄 수도 있습니다.

# Spring에서 DB 접근

## spring to db

- **Level 1: Pure JDBC (Java Database Connectivity)** 직접 데이터베이스와의 연결을 선언하고, raw SQL string을 작성한 후 쿼리의 결과로 반환된 ResultSet을 돌면서 작업을 수행합니다. 작성이 쉽지 않고 메모리 누수의 가능성이 높아서 현재에는 직접 사용되는 일은 드뭅니다.
- **Level 2: SQL Mapper (MyBatis)** 마이바티스는 sql을 xml 파일에 적으면서 변수를 입력할 수 있고, 쿼리로 반환된 결과를 DTO에 매핑하는 기능을 합니다. 또한 커넥션을 자동으로 관리하며, 모든 sql문을 직접 관리하므로 join이 많은 환경이나 복잡한 쿼리문이 들어가는 경우 아직도 선호되는 방법입니다.
- **Level 3: ORM (Spring Data JPA / Hibernate)** SQL을 객체지향적으로 다룰 수 있도록 도와주는 방법입니다. 테이블을 엔티티로 변환해서 매핑하고 hibernate가 자동으로 쿼리를 작성합니다. 단순 crud에는 성능 상 이점이 있지만, 대규모 데이터 처리나 다중 테이블을 처리할 때는 sql 최적화가 어려워서 배치나 쿼리 트리거 등 다른 방법을 사용하게 될 수도 있습니다.
