오늘은 NoSQL이 뭔지 배우고 MongoDB 실습을 해봤습니다.

## 1. NoSQL이란 무엇인가?
NoSQL은 **'Not Only SQL'** 의 약자로, 기존의 관계형 데이터베이스가 가진 고정된 스키마(Schema)와 수직적 확장(Scale-up)의 한계를 극복하기 위해 등장한 데이터베이스입니다.
### NoSQL의 핵심 특징
* **유연한 스키마**: 데이터의 구조가 고정되어 있지 않아, 언제든 새로운 필드를 추가하거나 수정할 수 있습니다.
* **수평적 확장성 (Scale-out)**: 서버의 성능을 높이는 대신, 값싼 서버를 여러 대 연결하여 용량을 무한대로 늘리기 쉽습니다.
* **비정형 데이터 처리**: 텍스트, 로그, 이미지 메타데이터 등 구조화되지 않은 방대한 데이터를 빠르게 처리하는 데 최적화되어 있습니다.
* **💡 NoSQL의 4가지 주요 타입**
1. **Document DB**: JSON, XML 형태로 데이터 저장 (예: MongoDB)
2. **Key-Value DB**: 단순한 Key와 Value의 쌍으로 저장 (예: Redis)
3. **Column-family DB**: 열(Column) 단위로 데이터 저장 (예: Cassandra)
4. **Graph DB**: 데이터 간의 관계를 노드와 엣지로 저장 (예: Neo4j)

1. ## 2. NoSQL의 대표주자, MongoDB 다양한 NoSQL 데이터베이스 중에서도 전 세계적으로 가장 널리 쓰이는 것이 바로 **MongoDB(몽고DB)**입니다. MongoDB는 'Document DB' 모델을 사용하며, 개발자에게 매우 직관적이고 친화적인 환경을 제공합니다. ### 왜 MongoDB를 사용할까? **① JSON 기반의 BSON(Binary JSON) 구조** MongoDB는 우리가 웹 개발에서 흔히 쓰는 JSON 형태(내부적으로는 BSON)로 데이터를 저장합니다. 자바스크립트나 자바(Java)의 객체(Object)를 그대로 데이터베이스에 넣고 뺄 수 있어 개발 속도가 비약적으로 상승합니다. **② 스키마 없는(Schemaless) 설계** MySQL에서는 테이블을 만들 때 컬럼의 이름과 타입을 미리 다 정해야 하지만, MongoDB는 같은 공간 안에 서로 다른 구조의 데이터를 유연하게 넣을 수 있습니다. 서비스 요구사항이 자주 바뀌는 스타트업이나 애자일(Agile) 환경에 아주 적합합니다. **③ 강력한 분산 처리와 고가용성** 데이터를 여러 서버에 나누어 저장하는 **샤딩(Sharding)**과, 장애 발생 시 다른 서버가 역할을 대신하는 **복제(Replication)** 기능을 자체적으로 강력하게 지원합니다. --- ## 3. RDBMS (MySQL) vs MongoDB 용어 비교 두 데이터베이스는 개념이 조금 다르기 때문에 사용하는 용어에도 차이가 있습니다. | RDBMS (MySQL, Oracle) | MongoDB | 설명 | | :--- | :--- | :--- | | **Database** | **Database** | 데이터베이스 (동일함) | | **Table** | **Collection** | 데이터가 모이는 논리적인 묶음 | | **Row (Record)** | **Document** | 하나의 고유한 데이터 단일 객체 | | **Column** | **Field** | 데이터의 속성 (예: 이름, 나이) | | **Join** | **$lookup (또는 임베딩)** | 관계된 데이터를 엮어내는 방식 | --- ## 4. 언제 무엇을 선택해야 할까? 무조건 MongoDB가 RDBMS보다 좋은 것은 아닙니다. 프로젝트의 성격에 따라 올바른 기술 스택을 선택해야 합니다. * **RDBMS를 써야 할 때**: 금융 시스템, 결제 시스템처럼 데이터의 무결성과 복잡한 트랜잭션 처리가 절대적으로 중요한 경우. * **MongoDB를 써야 할 때**: 실시간 로그 수집, 채팅 시스템, 게임 데이터, 혹은 서비스 초창기라 데이터 구조가 어떻게 변할지 예측하기 힘든 경우. ## 마무리 지금까지 NoSQL과 MongoDB의 기본적인 개념에 대해 알아보았습니다. 다음 포스팅에서는 Java Spring Boot 환경에서 실제로 MongoDB를 연동하고 데이터를 다루는 방법을 정리해 보겠습니다!
